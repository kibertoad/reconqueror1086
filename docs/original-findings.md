# Findings from the owned original

This register records compact, non-copyrightable facts derived from the user's installed GOG release. It deliberately does not contain extracted binaries, resource dumps, long dialogue, or media.

## Confidence scale

| Grade | Meaning | Can be treated as factual? |
| --- | --- | --- |
| Confirmed | Directly measured in the identified files, or unambiguous executable text/structure | Yes, for the hashed GOG build below |
| Corroborated | Independent documentation agrees with binary/resource evidence, but the exact executing code path has not been recovered | Usually; not necessarily an exact formula or table |
| Provisional | Plausible implementation chosen to make the game playable while exact original behavior remains unknown | No |

Confidence applies narrowly to the stated claim. Finding a name near joust resources, for example, proves that the identifier is present; it does not prove an opponent's odds or wager.

### Dragon run target timeline

The hashed `C1086.GOB` contains 486 directory entries, 10 of which have equal stored and expanded sizes. Across the GOB and 99 imported `.RES`/`.LOW` scene archives, the installer extracts every supported byte-stored, kind-1, and kind-2 resource through a centralized codec registry. A disposable end-to-end import of the hashed installation produces 29,226 manifest entries, including the five decoded kind-2 resources. Extensions remain hints rather than proof; known formats are validated before runtime decoding.

Dragon input is further **Confirmed** by static control flow. The mouse handler at `0x849C1`–`0x849C7` writes interrupt-supplied x/y directly to object-2 globals `+0x207E8/+0x207EC` when the position flag is set. Setter `0x7234C` invokes mouse interrupt `0x33` function 4 to set a position, then function 3 to read those same coordinates back into the globals. Event classifier `0x63114` can return code 3 to the dragon worker at `0x1BA83`, which ends its active input pass, but the precise mouse-button sequence, cursor artwork, and processor-dependent timing remain **Provisional**. The runtime's gold pointer crosshair and keyboard/controller aim are host presentation and input policy, not recovered original graphics.

Dragon event timing has a narrower **Confirmed** numerical map. Mouse callback `0x849E6`–`0x84A2C` queues the first four set button-event bits in a 20-byte record with timestamp, pointer x/y, and event type `(bit index - 1) & 3`. Initialization calls `0x6306C` with `(4,4)` at `0x72329`–`0x7232D` and `0x8492C`–`0x84930`, setting both classifier windows to four source timer units. For queued type 1, `0x6317A`–`0x631D0` returns code 3 only when `eventTime - lastType0Time < 4` and `eventTime - lastType1Time >= 4`; the shorter repeat returns 4 and the longer first interval returns 2. Worker `0x1BA83`–`0x1BAB6` clears its active-event flag on return code 3, then continues the movie-boundary path. This establishes the source event predicate and, together with the timer-chain map below, a nominal four-unit interval of about 220 ms from an aligned zero phase, but no separate score mutation. The runtime samples the host's current pointer on the first dragon update, matching the already-populated raw source globals, then uses host movement/controller events. Reproducing the source's timer-unit and busy-loop event throughput remains Provisional.

Dragon entry and victory dispatch are **Confirmed** by the executable path at `0x13168`–`0x134D9`. After movement/contact processing, the distinguished player record named by `AE6C` tests its grid pair against `(63,116)`, `(62,114)`, `(64,115)`, `(63,114)`, and `(63,113)`. A match reaches `0x1330C`, calls `0x1BB5C` at `0x13328`, then tests only that wrapper's return value at `0x13338` before its victory/failure branches. The wrapper reads lance experience and the three possession slots for the worker's score; this entry path has no independent strength or full-equipment predicate. The former minimum-strength/all-three-items entry and post-score victory gates are **Disproved**. `OriginalStrategicMovement.IsDragonEntryCell`, `OriginalStrategicPlayerPassResult.DragonEntryTriggered`, `Campaign.BeginDragonBattleFromStrategicMap`, and the map host now activate this path.
