## Observation

`C1086.GOB`, the 50 `CD:CONQUER/*.RES` files and the 49 `CD:CONQUER/*.LOW` files each begin with the
four bytes `.RES` and a `UINT32LE` directory offset. At that offset is a `UINT32LE` entry count and
then that many 52-byte records: a 32-byte name padded with NUL bytes, then five `UINT32LE` fields
at `+0x20` (kind), `+0x24`, `+0x28` (stored size), `+0x2C` (expanded size) and `+0x30` (data
offset). In all 100 files:

- the directory ends exactly at the end of the file;
- the records are in the order of their data offsets, and each entry's data starts where the
  previous one ends, the first at offset 8 and the last ending at the directory, apart from one gap
  of 1,236 bytes before `FNT6.PCX` in `SKIRMISH.RES`;
- no two names in one file are equal when case is ignored, and no directory is sorted by name;
- the field at `+0x24` is 0 in all 26,762 records;
- the kind is 0, 1 or 2. Kind 0 entries have equal stored and expanded sizes. Kind 1 and kind 2
  entries have a smaller stored size, except the two `Pal102` entries of `BAR0.RES` and `BAR0.LOW`,
  kind 1 with 256 bytes stored and 256 expanded, which decode as kind 1 streams (FND-RES-003).

The files hold 26,762 entries: 486 in `C1086.GOB`, 13,147 in the `.RES` files and 13,129 in the
`.LOW` files, 26,276 in the scene files together. `C1086.GOB` has 10 kind-0 entries (`rt_1_12.rat`,
`men8.CSF`, `credit.CSF`, `ica.CSF`, `ics.CSF`, `icw.CSF`, `utility.666`, `ffonta2.fnt`,
`richard.pcc` and `intro.666`), 471 kind-1 entries and 5 kind-2 entries (`configit.666`,
`prog.pcx`, `champion.pcx`, `crowning.pcx` and `death.pcx`). The scene files have 3,546 kind-0
and 22,730 kind-1 entries. The largest expanded size is 1,648,136 bytes (`credit.CSF`).

Each `.LOW` file holds the entries of the `.RES` file of the same name, with the same names apart
from the `TEX` dimensions and in the same order. A `TEXnnn w h` entry of a `.RES` file is
`TEXnnn w/2 h/2` in the `.LOW` file, halved with the remainder dropped, so `128 201` becomes
`64 100`, except 17 textures whose `.LOW` height is not half: `TEX119` to `TEX133` of `OFFICE`
(`128 201` against `64 89`) and `TEX006` and `TEX010` of `R022` (`128 104` against `64 67`).
Four texture entries of `R193` and the `Scenario` of `R022` have kind 0 in one file of the pair and
kind 1 in the other.

The scene files other than `SKIRMISH.RES` each hold `Viewer`, `Scenario`, `Map`, `Blocks`,
`SFXDEFS`, `POV`, `Backdrop`, the 128 colour maps `Pal0` to `Pal127` and their `TEX` textures;
46 also hold `BackImage`. `SKIRMISH.RES` holds 18 named files: `SKirmsnd.666`, `skirmish.csf`,
`skirmish.svg`, `skirmish.sfg`, and the pictures and palettes `MELEE2.PCX`, `MELEE2.PAL`,
`SK_START.PCX`, `SK_START.PAL`, `BRAWL.PCX`, `BRAWL.PAL`, `SKIRMCUR.PCX`, `SKIRMISH.PCX`,
`SKIRMISH.PAL`, `HELP.PCX`, `HELP.PAL`, `EXIT.PCX`, `STAIRS.PCX` and `FNT6.PCX`.

## Interpretation

The GOB and the scene files are one container format. The data area has no structure of its own:
an entry is found only through its record. The fields the game reads are described in FND-RES-002.

## Alternatives

The one gap in `SKIRMISH.RES` may be an entry that was removed or replaced after the file was
written; nothing reads it.

## How to reproduce

Read each file's header and directory, sort the records by data offset, and compare each offset
with the end of the previous entry. Decode every entry as FND-RES-003 and FND-RES-004 describe and
compare the output length with the expanded size.
